# Agent notes for this repo

Chrome MV3 extension; plain JS, no build step for the source. Read README.md first; status lives in REVIEW_READY.md and docs/.

- Load path for review is `build/review-unpacked` (made by `node tools/build.mjs build/review-unpacked`). Only rebuild it when promoting a verified build; tell the user to click Reload.
- Since the cut-over (R-24, 2026-10-03) `build/review-unpacked` is also the user's everyday extension. Its path is permanent: the extension's ID, and with it the user's saved presets and settings, derive from the folder path. Never move, rename or delete it; promote only verified builds into it. The old 1.1.0 folder was archived and removed on 2026-10-03 after the user confirmed its card was gone (R-24); what remains is the zip named below and the tag `v1.1.0-extraction-baseline`.
- Verify with `cd tests && npm test` and `node browser/run.mjs <builtDir> --label <name>`. The harness must stay isolated: temp profile, all non-local hosts blocked, `--mute-audio`, synthetic fixtures only. The test graph runs at the Mac's default output rate (48 kHz or the user's 96 kHz DAC); the level readings are exact-frequency and rate-independent, so never compare against FFT-bin numbers.
- Chrome caps a toolbar popup at 600 px tall and 800 px wide; the screen is 440 px wide and must stay under 600 px (W-NO-DEAD-SPACE enforces it). No emoji in the UI (unit test); icons are inline SVG symbols in popup.html.
- Shell hygiene: never put backticks in a double-quoted `git commit -m`; write messages to a file and use `-F`.
- Never: delete or unpack-and-edit the archived 1.1.0 copy (`…/T3 Code/t3-nightly-toy/tidal-miniplayer-extension-1.1.0-retired-2026-10-03.zip`), touch the user's Chrome profile or live install, contact Tidal with the user's session, capture real tabs or microphone, broaden permissions or CSP (the one addition so far, `sidePanel`, is decision R-20), add a manifest `key`, publish to the Web Store, change the repo's visibility again (public since 2026-10-03 at the user's request, decision R-22), or force-push.
- Don't fake success or invent data in the UI. Label demo data.
- Pitch is a key shift in semitones since 1.4.0 (P-01, the user's instruction of 2026-10-03); the speed control is gone. Don't bring playback-rate changes back without the user's OK.
- The audio processing is frozen (the user's words, 2026-10-04: "don't change anything about the audio processing without asking me first"). The default signal path must stay measurably identical build to build (W-DYN-BASELINE holds the 1.4.0 numbers). New processing goes in as a switchable alternative with the current behaviour as the default, and only after the user has said yes to that alternative in that conversation. The alternatives of 1.5.0 (bass-only leveler, slow release, loudness match, look-ahead limiter, warm ceiling) were asked for by the user ("build these so I can switch between them in the app ... just preserve the current sound").
- Presets are the user's. Never add, rename, re-tune, reorder or remove a factory preset, and never migrate stored presets, without the user's explicit OK in that conversation (rule R-07, 2026-10-01). Propose first, with the exact before/after list.
